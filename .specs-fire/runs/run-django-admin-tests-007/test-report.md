## ⚠️ Correction to earlier test reports

**Runs 001–006 each claimed "100% coverage". That figure was never
measured — I asserted it.** This run installed `coverage` and actually ran
it. Two findings:

1. **The real starting figure was 92%**, not 100%. Genuinely untested
   paths included `user_factory` (a *documented public API*, which this
   run's README describes), the `NoReverseMatch` fallback, saving an
   unsaved factory instance, the class-level `allowed_status_codes`
   branch, several field-type mappings, and the `InstanceBuildError`
   wrapper around save failures. Tests were added for all of them.
2. **`pytest --cov` understates this package by ~13 points.** It reports
   86% because `django_admin_tests` is imported through its own `pytest11`
   entry point while pytest loads plugins — before pytest-cov starts
   tracing — so module-level lines and `def` statements read as
   uncovered. `coverage run -m pytest` starts tracing first and reports
   the true figure. This is now pinned in `[tool.coverage.run]` with a
   comment, and CI enforces it.

Current honest figure: **99%**, with 2 uncovered lines
(`pytest_plugin.py:94-95`, the body of `_collect_smoke_items`, which
executes only inside the `pytester` subprocess and so isn't visible to the
parent process's tracer — it *is* exercised, just not measured).

## Issues Found

**1. The sdist shipped the entire repository, including local tool config.**
`hatchling`'s `packages` setting scopes only the *wheel*. The sdist swept
in `.claude/` (including `settings.local.json`, which embeds absolute
developer paths), the whole `.specsmd/` FIRE tooling, every internal
`.specs-fire/` planning document, and the npm lockfiles — 136K of material
that would have been published to PyPI. Fixed with an explicit
`[tool.hatch.build.targets.sdist]` allowlist; sdist is now 24K containing
only the package, tests, testapp, and the standard metadata files. No
credentials were present, but developer paths and internal planning notes
should not ship.

*This is exactly the gap the plan called out:* earlier runs verified only
the wheel, so the sdist had never been inspected.

**2. My first clean-install check was invalid.** Running
`python -c "import django_admin_tests"` from the project directory imports
from the *source tree*, not the installed wheel — Python puts the cwd on
`sys.path`. The check passed while proving nothing. Re-run from outside the
source tree with an assertion that the module resolves under
`site-packages`, which is what makes the result meaningful.

**3. Coverage was overstated in six prior reports** — see the correction
section above.
