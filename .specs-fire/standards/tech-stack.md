# Tech Stack

## Overview

A pip-installable Django app that other projects add as a dependency to get automatic admin smoke-test coverage — every registered `ModelAdmin`'s changelist, add, and change views are asserted to return 200 (or another allowed status) as part of the *host project's own* test run, regardless of whether that project uses Django's native test runner or pytest.

## Core Technologies

### Language

**Primary**: Python
**Version**: 3.10+ (developed against 3.12)

### Framework

**Framework**: Django
**Version**: 4.2 – 5.x (support Django's current LTS + latest release)
**Rationale**: Django is both the host framework this package plugs into and the source of the admin interface it tests.

### Test Authoring Style

**Style**: `unittest`-based Django `TestCase` subclasses — **not** pytest-native fixture functions.
**Rationale**: Django's `manage.py test` only discovers `unittest`-style tests, while pytest (via pytest-django) runs `unittest.TestCase`s transparently. `TestCase` is therefore the only format that works under both runners; pytest-native tests would lock consumers into pytest.

### Runtime

**Runtime**: CPython
**Version**: 3.10 – 3.12

## Supported Test Runners (host project side)

| Runner | How it picks up our tests |
|--------|---------------------------|
| `manage.py test` (Django native) | Host project imports our `TestCase` subclass into one of their own `tests.py`/`tests/` modules (one-line import) |
| pytest (+ pytest-django) | Same one-line import works via unittest support; optionally, our `pytest11` entry-point plugin auto-discovers and registers the smoke tests with zero user-side code |
